# codex-zig-ladder: general code review

Reviewed at `8a74c94` (2026-08-19) by Marley for Steve, at Damian's request. Scope: the whole tracked tree — the Python transports and VM drivers, the banking and harness generators, the shell/PowerShell orchestration, and the docs against the code. Every finding below was read in the source; the high-severity ones were re-checked by hand. Line numbers are at `8a74c94`.

## Verdict in three sentences

The core verdict path — `allcycles.sh` → `arm_for` → `zig_verdict` → `split_truth.py` — is carefully built, fails loud in every way I could construct, and is documented with the incident that motivated each guard, which is rarer than it should be. The real weaknesses sit at the seams around that path: **banking infers provenance from timestamps instead of recording it**, the **three QEMU drivers are copy-paste siblings that have drifted** (PRIORITIES item 7 is a direct symptom), stale artifacts (`.truth`, `.diags`, `plug-source.codex`) are not cleared before the step that regenerates them, and ten bundlers still carry a workaround the README says was deleted. None of it shows a wrong `ORACLE PASS` from the sweep itself; several show a wrong bank, a wrong warmup, or a hang where a failure should be.

## What is genuinely good

- `split_truth.py` refuses every look-alike: no marks, output before the first mark, missing END, unknown or duplicate rung. The silence rule in `allcycles.sh:19-31` is gated on exit status and the marker, so a stray "ORACLE" in captured text cannot flip a failure. `LADDER_RUNGS` / `LADDER_UNITS` cross-check at source time in both directions.

- `ring_compile.py` writes its output only on success, which is what makes the `rm -f` + `[ -s ]` discipline in `oracle_lib.sh` hold everywhere it is used. SIZE-framed reads with an explicit short-read failure; diagnostics never discarded; the VM stopped for every ring-cell write.

- The parity proof (`pcap_parity.py`) instead of a vote; `seed_identity.py` deriving the bank label from the seed's own hash; `ladder_root.py` refusing to guess; `check_paths.py` proving the wiring in seconds.

- The docs: the banked-against table first and allowed to be unflattering; "What the check proves, and what it does not" scrupulous about DDC scope; `JUSTIFICATIONS.md` as a separate register of measurements so rules need not re-argue themselves; a `.gitignore` annotated line by line. `emit_harness.py` as the one home for the pipeline text the six back-end generators share.

## Findings, most important first

Severity is about consequence for the ladder's claims, not code-smell size.

### A. Banking can record a wrong or mixed set and nothing downstream can tell

- high — `bank_truth.py:85-88,128`. The bank is stamped with whatever seed is on disk now; nothing records which seed produced the working `ast/*.truth`, and `seed_identity.require_match` has zero callers (README step 3 admits this). Truth arms under seed A, `CODEX_ROOT` repointed or pulled to seed B, `bank_truth.py` writes A's measurements into `truth/uB/` with a SEED file saying B. Fix: have `truth_arm` write the seed sha beside each `.truth` (a `.truth.seed` sidecar, or a first-line stamp that `split_truth` emits) and have `bank_truth.py` refuse on mismatch.

- high — `bank_truth.py:125-128`. `dest.mkdir(exist_ok=True)` + per-file `copy2` + SEED last: a `--force` into an existing slug, or a crash mid-loop, leaves the previous bank's files beside the new ones with no marker, and the directory reads as a complete fourteen-rung set — the exact "partial bank reads as a whole one" the docstring warns about. Write to a temp dir and rename, or purge `<slug>-*.truth` first.

- med — `bank_truth.py:48-74,111`. Staleness compares truth mtime to the git committer time of the newest watched-file commit. A branch switch to a harness that last changed earlier than the truths passes as fresh. Content identity (hash of the generator set, recorded beside the truth) is the honest key; see 1.

- med — `bank_truth.py:100-103`. The watermark globs every `gen_*_harness.py` and `bundle_*.ps1`, including non-rung tools (`gen_irmem`, `gen_zigc`, `bundle_zigemit`, …); a comment commit to one marks all fourteen truths stale — the cry-wolf `check_bundles.py:61-68` already fixed for itself.

- med — `bank_truth.py:134-138`. Pruning sorts bank dirs by directory mtime; overwriting files in an existing dir does not bump it on Linux, so re-banking the oldest of >`--keep` Updates can delete the bank just written. `iterdir()` would also rmtree any non-bank subdirectory of `truth/`.

- med — `ast/verify_merge.sh:15,36` via `ast/oracle_lib.sh:110,134`. `python3 gen_${m}_harness.py` and the blob-writing heredoc in `truth_arm` are unguarded and rely on the caller's `set -e`; `verify_merge.sh` runs only `set -u` and calls `truth_arm "$u" || …`, which disables errexit inside the function. A crashed generator leaves yesterday's `FibxHarness.codex` on disk, the bundle is unchanged, the truth reproduces the bank, and the script prints `MERGE VERIFIED` — the wrong-PASS it exists to rule out. Cheap fix: `rm -f` the harness first and `|| return 1` both steps.

### B. The QEMU drivers have drifted apart, and the drift is where the hangs are

- high — `ring_compile.py:150-154`. This is PRIORITIES item 7, located: the pre-READY wait `while b"READY\n" not in buf: buf += ctrl.recv(4096)` never checks for `b""`, so once QEMU exits the ctrl socket returns EOF instantly and forever — a tight 100% spin with no log output. The 120 s timeout covers only a live-but-silent guest. `codex_vm.wait_ready` (`codex_vm.py:69-77`) already has the EOF check and was not reused. The refill loop (186-213) and output loop (224-244) do fail loud on a dead guest; item 7's "read/refill loop" wording should be corrected along with the fix.

- high — `plug_run.py:137-139,158-169`. A QEMU death mid-emission (OOM kill, abort) is indistinguishable from the plug's clean close: the kernel FINs the slirp socket, `conn.recv()` returns `b""`, `closed=True`, a truncated `.zig` is written and `True` returned. No `proc.poll()`, and the serial "OK defs=N" status is printed but never asserted. `zig build-exe` usually turns this into a spurious red, not a false green — but it is the "silence looks like success" class the comment at 100-103 warns about, and `ring_compile`'s SIZE length check catches the equivalent.

- med — `codex_vm.py:56-67`. `launch()` orphans a QEMU when `connect()` raises (data connected, ctrl not): `Popen` is outside any try/finally and the caller's `finally: proc.kill()` has not been entered. With `wait=on` chardevs the orphan holds 3 GB forever. `plug_run.py:41` inherits this; `ring_compile.py:126-139` got it right.

- med — `ring_compile.py:125-148,219-287` vs `codex_vm.py:17-77,118-163`. Launch argv (incl. the 0xFE8 RAM cell), `free_port`, `connect`, the READY wait and the SIZE-aware reader are copy-pasted and already diverged: `ring_compile` hard-codes `-accel tcg` ignoring `CODEX_ACCEL`, dropped the EOF check (7), and grew the diags census that `compile_blob` lacks. One `launch(kernel, extra_args)` + one `read_size_framed(sock, timeout)` in `codex_vm.py` removes the class. Same for port 9145 defaulted in three files and `~/.local/pwsh/pwsh` hard-coded in seven.

- med — `plug_run_checked.py:54-61` + `pcap_parity.py:40-43`. The parity proof passes vacuously on an empty or partial capture: header-only pcap → `segments()` is `[]` → zero odd frames → "trusted". Nothing asserts the captured host→guest payload covers `len(msg)`; a dump that failed to attach or was cut by the un-`wait()`ed SIGKILL at `plug_run.py:171` reads as clean. One coverage check (`sum(plen) >= len(ir)+5`) makes it loud.

- med — `ring_compile.py:57-70,84-89`. gdb RSP framing returns on the first `#` and never consumes/validates the checksum; `cont_nowait` may then `recv(1)` a stale checksum digit instead of the `+` ack. It works today only because leftovers can never be `$`/`#`; a NAK or split packet desyncs silently. Every refill round does 3+ exchanges with the VM halted, so proper framing is cheap insurance.

- med — `seed_identity.py:44-52`. `update_label` labels any seed whose 8-hex prefix appears in any note, so interim seeds get release numbers (demonstrated: a checkout on `800A7683`, named in `GitHubUpdate48.md` as an "interim mirror push", is labelled "Update 48, truth/u48"); prior-release seeds appear in two notes and only `sorted()` order picks the right one. Restrict to the note's own release header.

### C. Stale artifacts not cleared before the step that regenerates them

- med — `ast/oracle_lib.sh:197`. `<rung>.truth` is not removed before the run/split, so a truth arm that fails at run or split leaves the old `.truth`; the next `zig_verdict` diffs against it and can print `ORACLE PASS`. `rm -f $(unit_rungs $m).truth` before the run fails closed.

- med — `ast/oracle_lib.sh:147-167` + `ring_compile.py:261-264`. `.diags` is written only when non-empty and never removed, so a compile that goes clean leaves last run's diagnostics for `check_diags.py` to judge, and `allcycles.sh:43`'s census (`ast/*.diags`, which also sweeps in arith/irmem/guardprobe/codexir/ringplug) keeps a class "present" that vanished — defeating the "POPULATION MOVED … now absent" detection `check_diags.py:143-154` claims. This is also why the pins "move whenever the unit list does" (PRIORITIES 8).

- med — `cycle.sh:13-22,52-53`. `plug-source.codex` is not removed before the re-bundle, `pwsh -Command` runs without `$ErrorActionPreference='Stop'`, and the fingerprint is computed from the two source files rather than the bundle actually compiled — so a bundler failure that exits 0 compiles yesterday's bundle and stamps today's fingerprint, and `plug_provenance` passes. `ast/ringplug_build.sh:341,357` does this correctly (rm first, hash the bundle); mirror it. Related: the TCP plug's fingerprint covers only `ZigEmitter`+`ZigPlug`, the ring plug's re-bundles and compares, so the two guards are inconsistent and the TCP one misses `IRTextParser.codex`/`PlugTypes.codex` moving.

- med — `tonight.sh:280`. Compiles `ast/guardprobe.cdx` without `rm -f` and runs it unconditionally, so a failed compile runs yesterday's binary and prints "BARE METAL SAYS" from it.

### D. Checks that report but do not fail

- med — `cycle.sh:58-68`. `WARMUP DIFF` never changes the exit status (`|| true`, no fail flag), so `cycle.sh hello recurse fib` exits 0 with divergent warmups. README calls this the check that runs "before any rung is worth running" — it reports but never refuses.

- med — `check_diags.py:85-93` vs `:140-141,164-166,180`. The comment says a CDX2064 reappearance "is a stopped rung, not scroll", but NOTE verdicts never affect the return code and pinned-count drift is only printed, only under `--census`. A CDX2064 reappearing (pinned 0) passes every rung and the sweep with rc 0.

- med — `ast/f4_boot.py:46-50`. `parse_sections` does `int(val)` on every line before the first `---`; the current dump has `emit-diags 0` followed by a bare `.` from `print-diags`, so `int('')` raises. This documented consumer (README "Consumers of what the ladder emits") has been dead since the diag walker landed.

- med — `ast/plugcycle.sh:17,20-22`. Hard-codes `zig_arm` instead of `$(arm_for "$m")` (so `plugcycle.sh fibx` pushes 13 MB over TCP), and the "what zig rejected" inventory greps `${m}.zigout` where `zig_verdict` writes zig's errors to `${m}.zigraw`.

### E. A workaround the README says was deleted is still in ten bundlers

- med — `ast/bundle_{lex,parse,desugar,scope,check,lower,text,pingpong,lir,fib}.ps1`. The `deck-record → subj-deck-record` global rename still runs, although README:613-617 says it "outlived the finding Update 43 closed", "silently disabled the seed's deck discipline in every bundle", and was to be deleted; `bundle_fibx.ps1:123-144` removed it only for fibx/whole and explains why. Nine of the ten carry `PhaseAllocator.codex`, and `gen_{lower,fib,text,pingpong}_harness.py` call `init-phase-allocator`, so those rungs run with the discipline off. Not a wrong PASS (both arms share the bundle) but a silently narrowed measurement contradicting the README's own rule about workaround hygiene.

- low — `pipefail` is set nowhere; `ring_compile.py … | tail/grep/head` appears in `oracle_lib.sh:148,154`, `arithcycle.sh`, `native_build.sh`, `ring_refill_test.sh`, `ringplug_build.sh`, `irmemcycle.sh`. ### I. Hygiene

- med — No tests for the Python tooling. The repo's thesis is "refuse rather than go quietly stale", and the refusers — `split_truth.py`, `bank_truth.py`, `seed_identity.py`, `check_diags.py`, `cce.py`, `pcap_parity.py`, the `--changed` carry logic — have no oracle. Findings 2, 5, 11, 13, 19, 20 are all things a small `pytest` file would have caught, and most are pure functions over strings and bytes.

- low — Tracked machine outputs: `corpus/run.json`, `run.jsonl`, `transpile.json`, `gaps.json` are rewritten by every full run (`corpus_run.py:326-327,361`; already clobbered once, `7d12733`). `pr67_clamp_reply.md` is a drafted PR comment at the repo root. ~15 probe chapters in `ast/` (`v-*.codex`, `ll-*`, `mut-probe`, `TokProbe`, …) have no reference from any script or doc. No `LICENSE` despite a public clone URL. `.agentgrid` not ignored.

- low — `errors='replace'` on both arms before diffing (`split_truth.py:103`, `oracle_lib.sh:184`): two different invalid bytes at one offset both become U+FFFD and compare equal. Narrow (dumps are ASCII) but it is a silent-PASS path; compare bytes, or `strict`. `plug_run_ring.py:71` writes the zig in text mode.

- low — `allcycles.sh:12` sends `ringplug_build.sh` stdout to `/dev/null`, where its `PLUG COMPILE FAILED` goes, so a ring-plug refusal kills the sweep under `set -e` with no message.

## If I were ordering the work

- Findings 7, 9, 8 — the unattended-runner hazards; all three are small. 7 is literally "call `codex_vm.wait_ready`".

- Findings 1, 2, 14, 16 — record seed identity beside each truth, make the bank atomic, clear `.truth` before run, rm-then-hash in `cycle.sh`. These close the only paths I found to a wrong bank or a wrong `PASS` from a stale artifact.

- Finding 29 and the README seams (30-32) — a newcomer reading the README today is told something the banks contradict.

- Finding 22 — delete the rename from the ten bundlers, re-bank, and let the bank-to-bank diff prove it image-preserving the way `JUSTIFICATIONS.md` already does for the other bundle edits.

- A `tests/` directory for the refusers (34), then the consolidation work (10, 26, 28) can be done with a net.

A closing note on tone: almost every finding here is at an edge the core was built to protect, and several (7, 15, 34) are things the repo's own PRIORITIES already names. That is the mark of a project that knows where its seams are. The gap is between knowing and having written it down in the form that refuses.
